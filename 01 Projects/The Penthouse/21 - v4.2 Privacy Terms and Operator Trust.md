# v4.2 Privacy Terms and Operator Trust

This release is about trust before scale. If I am going to let real people sign up, they deserve plain language about what the server does and does not promise. And I deserve real operator dashboards instead of placeholder zeros.

## Why v4.2 exists

The app worked. The data story did not. I had no public privacy policy, no terms of service, and the admin panel was lying to me with fake counters. v4.2 fixes both sides of that conversation.

## Privacy and terms

I added public `/privacy` and `/terms` routes. The copy is first-person and honest. It says the stack is self-hosted consumer hardware with no UPS and no redundancy guarantee. It names the actual third parties: GIPHY, Klipy, and ALTCHA. It gives a real operator email for data export or account deletion requests.

The pages are reachable before login. The registration screen links to them. Settings got a new Legal section. No one can claim they never saw the terms.

## Admin diagnostics

The admin dashboard used to show six silent counters. Now it shows four real sections:

- **System:** version, uptime, and whether this is a deployed build
- **Backups:** status and last successful backup
- **Push since start:** sent, failed, and stale removed
- **Errors since start:** count, last error, and route-group chips

The backup status reads from a real file when it is configured. If the file is missing or malformed, it degrades to unavailable instead of crashing.

## Backend hardening

Codex trimmed and hardened the backend in the same pass:

- Rate limiting is now one shared preHandler across login, password reset, and token refresh
- The notification service got a proper `stop()` and `drain()` so it does not leave stray work after restarts
- Reaction payloads and sync cursors are validated more carefully
- Postgres `22P02` errors map to 400 instead of 500
- Deleted-media date validation is stricter
- Admin summary collapsed five member-count queries into one conditional aggregate
- Dead code removed: `observability.ts`, `uploads.ts`, `settings.ts`
- Dropped `@fastify/static` and `pino-pretty`
- Caddy now sends `Referrer-Policy`, `X-Content-Type-Options`, and `X-Frame-Options` headers

## Version realignment

All package versions moved from `4.0.0-alpha.1` to `4.2.0-alpha.1` to match the rebuild line. The settings footer shows the real version. The admin summary reads it from `package.json` at runtime.

## Validation

- Typecheck: 0 errors across all workspaces
- Lint: clean
- Format: clean
- API tests: 232 passed
- Production build passed

## Risks still open

- The backup status file is read but not written yet. The host cron needs to produce it.
- Push stats are in-memory, so they reset on restart. The label says "since start" so that is honest.
- The dirty backend tree still needs to be split into clean commits before the next deploy.
