## Why this matters

`npm audit --omit=dev` reports 10 vulnerabilities (3 moderate, 7 high) in
packages that ship to production. Two matter: `socket.io-parser` (memory
exhaustion on malformed packets — this app's product *is* realtime chat) and
`undici` (response desynchronisation, cookie/header injection). Critically,
the committed `package-lock.json` pins the vulnerable versions while the
developer's `node_modules` already contains newer ones — so local runs and
`npm run validate` are patched, but every `npm ci` in CI and in the production
Docker image installs the vulnerable pair. The gap between "what I tested" and
"what deployed" is exactly the thing this repo needs to stop doing (see plan 003).

## Current state

- `package.json` (root) — npm workspaces (`apps/*`, `services/*`, `packages/*`),
  `engines.node >= 22`, plus an `overrides` block already used for exactly this
  kind of forced patch. Match that style.
- `package-lock.json` (root, committed) resolves:
  - `node_modules/socket.io-parser` → `4.2.6` (advisory range 4.0.0–4.2.6, HIGH)
  - `node_modules/undici` → `7.28.0` (advisory range 7.0.0–7.28.0, HIGH), pulled
    in by `isomorphic-dompurify@3.19.0` → `jsdom@29.1.1` → `undici`.
- Local `node_modules/socket.io-parser/package.json` says `4.2.7` — proof of the drift.
- `services/api/package.json` declares `socket.io ^4.8.3`,
  `socket.io-client ^4.8.3` (devDep), `isomorphic-dompurify ^3.14.0`. Latest
  upstream at planning time: `socket.io-parser 4.2.7`, `undici 8.10.1` (do **not**
  jump undici majors — `jsdom` chose 7.x; a `^7.29.x` override is enough).
- Realtime entrypoint: `services/api/src/realtime/socket.ts` (810 lines) — parser
  work happens below it, do not edit it for this plan.

## Steps

### Step 1: Record the "before" state

Paste the output of `npm audit --omit=dev` and
`npm ls socket.io-parser undici` into your final report. This proves the fix
was needed and lets the reviewer compare.

**Verify**: `npm audit --omit=dev | tail -5` → non-zero vulnerability count
("10 vulnerabilities (3 moderate, 7 high)" or similar).

### Step 2: Patch within the declared ranges

Run `npm audit fix` (no `--force`). This should update
`socket.io-parser` to `4.2.7` and leave `undici` on a 7.x.

**Verify**: `node -e "const l=require('./package-lock.json');console.log(l.packages['node_modules/socket.io-parser'].version)"` → `4.2.7`
**Verify**: `npm ls socket.io-parser` → shows `4.2.7`, no `INVALID`/`UNMET` lines.

### Step 3: Force undici within its major if Step 2 did not

If `npm audit --omit=dev` still lists `undici`, add one override next to the
existing ones in the root `package.json` (keep the existing entries untouched):

```json
    "overrides": {
      "@esbuild-kit/core-utils": { "esbuild": "^0.25.12" },
      "@sveltejs/kit": { "cookie": "0.7.2" },
      "undici": "^7.29.0",
      "uuid": "^11.1.1"
    }
```

Then `npm install --package-lock-only` to regenerate the lockfile.

**Verify**: `node -e "const l=require('./package-lock.json');console.log(l.packages['node_modules/undici'].version)"` → a `7.x` at or above `7.29.0`.

### Step 4: Prove a clean install matches the tested tree

The whole point of the plan: CI's `npm ci` must produce exactly what you tested.

**Verify**: `npm ci` → exit 0, then `npm audit --omit=dev` → `found 0 vulnerabilities`
(audit exits non-zero on any finding at the default level). If a *moderate*
advisory remains and is unreachable at runtime (build-time tooling), record it
in the report and note it in `plans/README.md`; do not chase it.

### Step 5: Run the gate

**Verify**: `npm run validate` → exit 0.
**Verify**: `npm --workspace @penthouse/api run test:integration` → all pass,
paying attention to `services/api/test/integration-realtime.test.ts` and
`services/api/test/media.test.ts` (the two suites most exposed to a parser change).

## Test plan

No new tests: this is a dependency patch, and the existing realtime and media
suites are the regression net. If `npm audit fix` cannot resolve a finding
without a major bump, STOP instead of writing tests around a version you picked.

## STOP conditions

Stop and report if:

- `npm audit fix` wants to change `socket.io` or `fastify` majors.
- Any integration test fails after the patch and the failure is not obviously
  caused by the version change (do not "fix" tests to make them pass).
- `undici` cannot reach ≥7.29.0 without bumping `jsdom`/`isomorphic-dompurify`
  majors — that is a primary-agent decision, not yours.
- The drift check shows `package.json`/`package-lock.json` changed since `2bea709`
  in a way that contradicts the excerpts above.
