# GPU mining — V100 + RX 9060 XT — 2026-10-21

Goal: the most **net** money per day (revenue after fees minus electricity), not the highest hashrate, from a Tesla V100-PCIe-32GB and an RX 9060 XT 16GB on the omarchy PC that loses power under sustained load. Same method as [[Strata V100 tuning — 2026-10-18]]: every lever measured on the real cards, one change at a time, under the thermal watchdog (`~/llm-trade-bench/tools/guarded-run.sh`), priced with live WhatToMine data at the US-average **18.31 ¢/kWh**.

Account identifiers (Kryptex mining username, payout wallet) are kept out of this note on purpose; they live in `~/opt/miners/mining.env`.

Kryptex's own estimates agree with the measurement (Pearl ≈ $0.038/TH/s/day, Quantus ≈ $0.0057/MH/s/day; Kryptex's Quantus price is ~8 % below WhatToMine, likely its margin). Electricity counts GPU watts only; PSU losses cost ~$0.12/day more.

Baseline before this work: unMineable BeamHash III, both cards ≈ **$0.29/day gross, ≈ −$0.6/day net**. The jump came from moving to 2026-era compute-bound algos, not from pool choice.

## How it runs

User systemd units, **not enabled at boot**:

- `mining.target` → `mine-v100.service`, `mine-9060.service`, `mine-watchdog.service`
- `mine-v100`: guarded OneZeroMiner, sets the V100 PL from `mining.env` on start, back to 135 W on stop. `Conflicts=unbiasedstrata.service llama-nv.service`, so starting Strata stops V100 mining and vice versa.
- `mine-9060`: guarded SRBMiner with `CUDA_VISIBLE_DEVICES=` and `--gpu-id 0`, applies the −30 mV offset on start and 0 on stop. `Conflicts=llama-amd.service`.
- `mine-watchdog` (`~/opt/miners/bin/mine-watchdog`): stops everything if the 9060 junction ≥ 90 °C or memory ≥ 88 °C; restarts a miner whose API hashrate reads zero for 5 minutes.
- guarded-run stops a miner at V100 ≥ 83 °C, CPU ≥ 92 °C or low RAM and exits 99; the units do not restart after 99.
- Settings: `~/opt/miners/mining.env`. Bench harness: `~/opt/miners/bench/` (`minerbench.sh`, `uv-sweep.sh`, `mclk-sweep.sh`, `runs/`).

```bash
systemctl --user start mining.target      # start (stops Strata)
systemctl --user stop mining.target       # stop, V100 back to 135 W, 9060 offset 0
journalctl --user -u mine-v100 -u mine-9060 -u mine-watchdog -f
```

Root helpers (NOPASSWD sudoers): `/usr/local/sbin/v100-tune` (PL 100–150 W, clock lock) and `/usr/local/sbin/amd-tune` (offset −200..0 mV, cap 112–140 W, memory clock 500–1259 MHz, reset). Overdrive is on via `/etc/limine-entry-tool.d/amd-overdrive.conf` (`amdgpu.ppfeaturemask=0xfff7ffff`); `gpu-amd-power.service` re-applies the 112 W cap by PCI ID at boot.

## Stability record

- Combined load (V100 150 W + 9060 111 W = 261 W GPU) held 15 + 17 min in tests, then hours in service; peaks V100 62 °C, 9060 junction 72 °C / memory 64 °C. No crashes from mining itself (the 2026-10-22 21:15 power loss was a pulled plug).
- The 9060 runs its slot power through a **SATA-fed riser** — replace with a 6-pin- or Molex-fed riser before weeks unattended.

## 2026-10-22 plug pull → 9060 riser fault

After an accidental power pull the 9060 began hanging 7–15 min into every run (power drops to ~10 W, SRBMiner `GPU0 DEAD`, restarts never recover it), at −30 mV **and** at 0 mV, on the same kernel and packages that had run 9.5 h clean. The kernel's boot line shows why: the 9060's link at root port `00:01.2` now trains at **Gen1 x4 (2.5 GT/s)** where every earlier boot had **Gen3 x4 (8 GT/s)**, and at 23:52 it logged `device lost from bus!` with SMU reads returning `0xFFFFFFFF`. That is a marginal physical link (riser, its connectors or its SATA power), not tuning. Bandwidth itself is irrelevant for mining (Gen1 x4 = 1 GB/s is plenty).

Fix order: reseat riser both ends + SATA lead (different PSU cable) + card power; force the slot to Gen3/Gen2 in BIOS; confirm the boot line shows 8 GT/s; 9060 alone 30 min, then combined; replace the riser if it still trains at Gen1.

Check the link any time: `journalctl -k -b | grep "available PCIe bandwidth"`.

## Mistakes caught (keep these)

1. **SRBMiner 3.7.9 ignores `--disable-gpu-nvidia`** on pearlhash/quantus and silently mined on the V100 too, halving the V100's Quantus rate (373 → 166 MH/s) in the first combined run. Fix: hide CUDA (`CUDA_VISIBLE_DEVICES=`) and pin `--gpu-id 0`.
2. **guarded-run does not kill background children on normal exit** — wrapper scripts must trap EXIT and stop their miners.
3. **Watchdog read the wrong API field** (`total_hashrate` is under `algos[0]` in OneZeroMiner), saw 0, restarted a healthy V100 every 5 min until systemd's start limit stopped it: V100 idle 11:50–20:15 on 10-22. Check a watchdog against the live API before trusting it.
4. `/tmp` (the session scratchpad) is wiped on reboot — the bench harness now lives in `~/opt/miners/bench`.
5. Never gate a wait loop on `pgrep -f <name>` when that name is in the loop's own command line.
6. **Watchdog crashed on a lost card**: sensors return "Operation not supported", bash arithmetic on an empty string failed, and it crash-looped 2,439 times overnight. It now stops mine-9060 when sensors are unreadable, or when the card idles under 40 W with zero hashrate, instead of restarting it.
7. SRBMiner on the V100 took ~3 min to start while probing the dead 9060 over OpenCL. The V100 unit now points `OCL_ICD_VENDORS` at an NVIDIA-only directory, which also guarantees it never mines on the 9060.
