# v4.3 Collaboration Wave

The app started as a messenger. This wave turns it into a small-community platform. The goal is not Discord scale. The goal is groups that feel like actual rooms, with controlled access and privacy-first extras.

## Why this wave exists

One-on-one and small group chats were working. What was missing was the ability to find rooms, ask to join private ones, share invites, forward messages cleanly, and preview social links without giving away privacy. v4.3 builds those surfaces.

## Community screen

The main **People** tab became a full **Community** screen with four tabs:

- **People**: members you already know
- **Discover**: public and private groups you can join or request
- **Requests**: pending join requests for groups you manage
- **Invites**: invite links you created or can revoke

Discover uses compact cards. Each card shows the group avatar, description, member count, and whether it is public or private. Public groups let you join directly. Private groups send a request to the managers.

The **General** group is no longer automatic. It is an opt-in community hub. New accounts do not get dumped into it by default.

## Channel tabs

Groups now have channels rendered as a horizontal strip of underline tabs. The strip scrolls on small screens and shows a fade pointer on the right edge when there is more to scroll. Locked manager-only channels show a clear notice instead of looking broken or read-only.

## Invites and requests

Managers can create invite links with optional expiry and use limits. The default is 7 days and 25 uses. They can also make unlimited or never-expiring links. Each invite shows its status, use count, and expiry. Managers can copy, share, or revoke them.

The `/join?token=...` page handles redemption. It survives sign-in, so if someone clicks an invite while logged out they can authenticate and land in the group. The backend uses a one-time token returned at creation, not the database row ID.

## Forwarding

Messages can now be forwarded to several chats at once. The picker uses recipient chips and search. After you forward to a destination, that destination drops out of the retry list. That prevents duplicates if a later destination fails.

You can only see **View source** on a forwarded message if you belong to the original chat.

## Files

File attachment cards got a softer look. Readable text uses **Ubuntu**. Exact byte values use **JetBrains Mono**. Captions are normal weight, not bold. The cards show file type and size clearly. Uploading, failed, retry, expired-link refresh, unavailable, and downloaded states are all handled.

## Social embeds

Instagram, YouTube, and X links now render in their own bubble separate from message text. That way the text stays readable even if the embed fails or is blocked.

Embed loading follows a user-level setting:

- **Auto**: load previews immediately
- **Ask first**: show a gate and let the user decide
- **Never**: keep the link plain

The choice is saved to the user profile. The backend preview endpoint is rate-limited and times out after 4 seconds. It returns validated metadata only. It never returns provider HTML. Unsupported or failed URLs fall back to a plain original-link card.

The gate explains that loading shares IP and browser data with the provider. No external request happens before the user agrees.

## Backend wiring

- `GET /api/v1/embeds/preview?url=...` returns metadata for fixed YouTube, Instagram, and X URL shapes
- `POST /api/v1/messages/:id/forward` handles forwarding
- Group discovery, request-to-join, and invite routes are in `services/api/src/routes/groups.ts`
- Embed consent mode is stored in the user profile via migration `042_embed_consent_mode.sql`
- The list contract ceiling for People and discovery was raised to 200 rows
